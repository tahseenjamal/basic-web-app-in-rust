🦀 Rust  ·  Axum  ·  REST API

Basic Web App
in Rust

A minimal, idiomatic REST API demonstrating typed extractors, separate request/response structs, RFC 3339 timestamps, and clean modular routing — all on Axum + Tokio.

Rust 2024 axum 0.8 tokio 1 serde + time

⚙ Tech Stack

🕸
Axum 0.8
Ergonomic type-safe HTTP framework built on Hyper and Tower. Extractors turn request parts into typed Rust values at compile time.
⚡
Tokio 1
Multi-threaded async runtime. Each request runs as a lightweight task; tokio::main drives the event loop.
🔄
Serde 1
Zero-cost serialization framework. derive(Serialize, Deserialize) generates JSON encode/decode at compile time.
🕐
time 0.3
OffsetDateTime::now_utc() produces server-side UTC timestamps; time::serde::rfc3339 serializes them as ISO 8601 strings.

📁 Project Structure

src/ ├── main.rs Entry point — binds TcpListener, starts axum::serve ├── models/ │ ├── user.rs CreateUserRequest · GetUserQuery · User · handlers │ └── blog.rs CreateBlogRequest · Blog · handlers └── routes/ ├── routes.rs Merges all sub-routers into one Router ├── user_routes.rs /user GET + POST └── blog_routes.rs /blog GET + POST
💡
Input/output separation — request structs (CreateUserRequest, GetUserQuery, CreateBlogRequest) only derive Deserialize; response structs (User, Blog) only derive Serialize. This prevents server-generated fields like created from leaking into client input requirements.

🔌 API Endpoints

Method Route Input Status Description
POST /user JSON body: username, name 201 Create a new user
GET /user Query: ?username=<value> 200 Retrieve a user by username
POST /blog JSON body: username, name, tweet 201 Create a new blog post
GET /blog — 200 Retrieve the demo blog
POST /user
Creates a user from the JSON body. Returns the user with a server-generated UTC timestamp.
Required fields:
username: String name: String
GET /user
Looks up a user by username query param. Returns the user with a fresh server timestamp.
Required query params:
username: String
POST /blog
Creates a blog post from the JSON body. Embeds a User object and records the server timestamp.
Required fields:
username: String name: String tweet: String
GET /blog
Returns a static demo blog. No parameters required. Useful for health-checking the JSON serialization pipeline.
No parameters required.

Rust structs

// Input — POST /user body
#[derive(Deserialize)]
pub struct CreateUserRequest { pub username: String, pub name: String }

// Input — GET /user query string
#[derive(Deserialize)]
pub struct GetUserQuery { pub username: String }

// Output — all user endpoints
#[derive(Serialize)]
pub struct User {
    pub username: String,
    pub name:     String,
    #[serde(with = "time::serde::rfc3339")]
    pub created:  OffsetDateTime,       // server-assigned
}

// Input — POST /blog body
#[derive(Deserialize)]
pub struct CreateBlogRequest {
    pub username: String,
    pub name:     String,
    pub tweet:    String,
}

// Output — all blog endpoints
#[derive(Serialize)]
pub struct Blog {
    user:      User,
    tweet:     String,
    #[serde(with = "time::serde::rfc3339")]
    timestamp: OffsetDateTime,          // server-assigned
}
Rust

🚀 Getting Started

You need Rust installed (stable toolchain). No other dependencies.

git clone https://github.com/tahseenjamal/basic-web-app-in-rust.git
cd basic-web-app-in-rust
cargo run
bash

Server starts on http://127.0.0.1:3000. You will see:

🧠 Design Decisions

  • 1
    Separate input and output types. CreateUserRequest / GetUserQuery / CreateBlogRequest are input-only (Deserialize); User and Blog are output-only (Serialize). This prevents server-generated fields (created, timestamp) from ever being required in client requests.
  • 2
    Server-assigned timestamps via OffsetDateTime::now_utc(). Clients never supply timestamps. The time::serde::rfc3339 adapter serializes them to a standard, human-readable ISO 8601 string in responses.
  • 3
    Correct HTTP semantics. POST handlers return 201 Created; GET handlers return 200 OK. Axum's Json<T> extractor automatically returns 422 Unprocessable Entity if the request body is malformed or missing required fields.
  • 4
    Meaningful startup errors. expect("failed to bind — is port 3000 already in use?") surfaces a clear diagnostic instead of a cryptic panic if the port is already taken.
  • 5
    Stateless by design. No database — all responses are constructed at request time. To add persistence, inject a sqlx::PgPool into the router state and pass it to handlers via axum::extract::State.
